# Core Web Vitals audit — 14 August 2026

Issue #67 targets the top 20 impression pages. The Day 10 GSC file has no `topPages` rows because fresh service-account access was unavailable, so this audit uses the highest-impression unique URLs explicitly recorded in the authoritative page-level issue #57 and the 4 August audit. Query-level rows are not used for aggregate decisions.

## Measurement

Run `npm run report:cwv -- --output automation/reports/cwv-psi-2026-08-14.json`.

The script measures mobile and desktop with PageSpeed Insights and records Lighthouse performance, LCP, CLS, INP when exposed, available field metrics, total byte weight and main-thread work. `PAGESPEED_API_KEY` is optional but recommended. The PR workflow runs the same command (writing to `cwv-baseline-2026-08-14.json` at the repo root) and uploads the generated JSON as a CI artifact. Missing metrics remain null; the audit never substitutes zero for unavailable data.

**Do not write PSI output to `automation/reports/cwv-baseline-2026-08-14.json`.** That path is this audit's committed code-review snapshot (`schemaVersion`, `codeAudit`, `pages` as `[path, impressions, position]` tuples) and uses a different shape than the raw PSI measurement report (`generatedAt`, `source`, `pages` as objects with `mobile`/`desktop`/`errors`). The two files serve different purposes and must not share a filename.

## LCP findings

`DiscoverHeroImage` already uses `next/image`, explicit width/height, a reserved 16:9 wrapper and priority on above-the-fold tool heroes. Priority images now set high fetch priority explicitly.

Blog hero images also have explicit dimensions and a reserved 16:9 wrapper. `BlogHero` did not use state or browser APIs, so it is now a server component instead of a hydrated client boundary. Its hero image also uses high fetch priority.

## CLS findings

The standard calculator renders its `Estimated results` panel from default inputs on the initial render, rather than inserting the main result area only after a button click. The shared hero wrappers also reserve their aspect ratios. No visual redesign was made.

## INP / bundle finding

Generic result charts and tables are already dynamically imported. A remaining follow-up is `components/Calculator.tsx`, which still statically imports bespoke personal-loan, SIP, advanced-calculator and report modules at the shared client-router level. The safe next optimization is route-level code splitting while preserving server rendering for above-the-fold calculator content. This issue does not change calculator formulas or runtime routing.

## Thresholds

- LCP good: <= 2.5 s; poor: > 4.0 s
- INP good: <= 200 ms; poor: > 500 ms
- CLS good: <= 0.10; poor: > 0.25

Any measured failure should be handled page-by-page and compared again at the Day 36 checkpoint.
